# Использование

Сначала подготовьте среду по {doc}`инструкции установки <Installation>`. Команды ниже выполняются внутри Dev Container или гостевой Linux в VMware/UTM. Workspace готового образа находится в `~/clover2-dev`.

(simulator-launch)=

## Запуск симулятора

:::{important}
В готовом образе VMware/UTM среда уже подготовлена.  
Если используете Dev Container впервые, сначала выполните {ref}`загрузку зависимостей и сборку <simulator-first-build>`. Затем запускайте ту же команду в терминале контейнера с подключённым workspace.
:::

Откройте терминал внутри гостевой Linux и выполните:

```bash
ros2 launch clover2_sim gz_simple.launch.py
```

Для остановки симулятора нажмите `Ctrl+C` в этом терминале.

## Программирование в симуляторе

В симуляторе можно разрабатывать и тестировать код, используя тот же [фреймворк](../Programming/AutonomousFlight), что и на настоящем дроне.

Для удобства программирования в VMware/UTM установлен VS Code.

## Повторный запуск

После перезагрузки компьютера не нужно заново устанавливать среду или собирать неизменённый проект.

1. Запустите машину в VMware/UTM либо откройте `clover2-dev` в VS Code и выберите **Dev Containers: Reopen in Container**.
2. Откройте терминал внутри выбранной среды.
3. В готовом образе с настроенным окружением выполните команду запуска из раздела выше.
   ```bash
   ros2 launch clover2_sim gz_simple.launch.py
   ```

### Когда нужно пересобирать проект

Пересборка нужна, если:

- Вы впервые скачали исходники;
- Изменился C++-код;
- Изменились `CMakeLists.txt` или `package.xml`;
- Появились новые ROS 2-пакеты;
- Команда запуска не видит пакет;
- После `vcs import` были обновлены репозитории.

Для пересборки используйте:

```bash
cd ~/clover2-dev
colcon build --symlink-install
```

## QGroundControl

При использовании симулятора так же, как и на настоящем дроне, можно использовать QGroundControl для управления параметрами и просмотра телеметрии.

В образе VMware/UTM QGroundControl уже установлен и находится в меню приложений. При использовании Dev Container QGroundControl нужно установить на хостовой системе и запустить его.

Соединение с симулятором выполняется автоматически при запуске. Если QGroundControl не видит симулятор, проверьте, что в настройках QGroundControl включён **Autoconnect to UDP**.

## Render Engine

Используемый симулятор Gazebo поддерживает несколько движков визуализации.

Из-за особенностей эмуляции графики в VMware/UTM там используется старый движок `ogre1`, который обеспечивает высокую производительность и совместимость с графическими драйверами.

В Dev Container по умолчанию используется `ogre2`, который поддерживает более современные эффекты, но может быть несовместим с некоторыми видеокартами.

В случае проблем с отображением можно переключиться на `ogre1`, установив переменную окружения перед запуском симулятора или добавив в `~/.bashrc`:

```bash
export CLOVER2_GZ_SIM_RENDER_ENGINE=ogre
```

Или указав её в команде запуска:

```bash
ros2 launch clover2_sim gz_simple.launch.py render_engine:=ogre
```
